## WHAT WAS BUILT

### 1. New Method: `speakExact(text: string)` 
**File:** `lib/realtime/openai-realtime-client.ts` (lines 214-244)

**What it does:**
- Injects conversation.item.create event with exact text as assistant message
- Sends response.create event requesting audio synthesis only (no instructions)
- Returns immediately (fire-and-forget)
- Audio plays automatically via WebRTC

**Why this is safe:**
- ✅ Text is predetermined (not generated by model)
- ✅ No instructions field (can't trigger model reasoning)
- ✅ Only TTS happens (text-to-speech synthesis)
- ✅ No model inference = no drift possible

**Code:**
```typescript
speakExact(text: string): void {
  // Inject exact text as assistant message
  const itemEvent: RealtimeSessionEvent = {
    type: "conversation.item.create",
    item: {
      type: "message",
      role: "assistant",
      content: [{ type: "text", text: text }],
    },
  };
  this.sendEvent(itemEvent);

  // Request synthesis (no instructions, only TTS)
  const responseEvent: RealtimeSessionEvent = {
    type: "response.create",
    response: { modalities: ["audio"] },
  };
  this.sendEvent(responseEvent);
}
```

useEffect(() => {
  if (phase !== "voice_active" || !controllerRef.current) return;

  // Find last final user message
  const lastUserMessage = voiceTranscript
    .filter((entry) => entry.role === "user" && entry.isFinal && entry.text?.trim())
    .pop();

  if (!lastUserMessage) return;

  // Prevent double-processing
  const lastProcessedId = sessionStorage.getItem("lastProcessedTranscriptId");
  if (lastProcessedId === lastUserMessage.id) return;

  sessionStorage.setItem("lastProcessedTranscriptId", lastUserMessage.id);

  // Advance beat (no extraction, no validation, no intelligence)

}, [voiceTranscript, phase]);

## PROOF: OPENAI CANNOT GENERATE DIALOGUE

### Method Analysis

**speakExact() creates two events:**

1. **conversation.item.create** (exact text is injected)
   ```json
   {
     "type": "conversation.item.create",
     "item": {
       "type": "message",
       "role": "assistant",
       "content": [{ "type": "text", "text": "Hi, I'm Zeya..." }]
     }
   }
   ```

2. **response.create** (requests synthesis only)
   ```json
   {
     "type": "response.create",
     "response": { "modalities": ["audio"] }
   }
   ```

**Why generation is impossible:**
- ✅ Text already in conversation (not generated)
- ✅ No `instructions` field (can't trigger model)
- ✅ Only `modalities: ["audio"]` (TTS only)
- ✅ No inference path to model
- ✅ No reasoning authority given

### Comparison: Old vs. New

**Old path (DEAD):**
```
response.create { instructions: "You are a host..." }
  → OpenAI decides what to say
  → OpenAI generates response
  → Consulting drift happens
```

**New path (Phase 1B):**
```
conversation.item.create { content: "Hi, I'm Zeya..." }
response.create { modalities: ["audio"] }
  → Realtime synthesizes existing text
  → NO model inference
  → NO drift possible
```
