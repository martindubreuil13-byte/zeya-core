# MemoryEvent Architecture

## Overview

MemoryEvents bridge CallOutcomes to Zeya's memory system. Every conversation outcome is automatically converted to a memory event that feeds into the learning and strategy engine.

**Flow**: CallOutcome → MemoryEvent → Memory System → Strategy Adjustment

---

## The Conversion Pipeline

```
CallOutcome (from webhook)
├─ outcomeId: outcome_xxx
├─ outcome: "interested"
├─ confidence: 0.85
├─ conversationId: conv_xxx
├─ workerBriefId: brief_xxx
└─ summary: "Prospect interested in demo"
       ↓
MemoryEvent (automatically created)
├─ memoryEventId: mem_xxx
├─ memoryType: "lead_interest_detected"
├─ source: "call_outcome"
├─ sourceId: outcome_xxx
├─ confidence: 0.85
├─ conversationId: conv_xxx
├─ workerBriefId: brief_xxx
└─ payload: {summary, recommendedAction, callDuration, ...}
       ↓
Memory System (Phase 12C)
├─ Index by workerBriefId
├─ Index by memoryType
├─ Track frequency and patterns
└─ Feed into learning loop
```

---

## Outcome → Memory Type Mapping

| CallOutcome | MemoryType | Use Case |
|------------|-----------|----------|
| **interested** | `lead_interest_detected` | Prospect showed interest; schedule follow-up |
| **callback_requested** | `callback_requested` | Prospect asked for callback; schedule reminder |
| **not_interested** | `lead_disqualified` | Prospect declined; remove from list |
| **wrong_number** | `wrong_number_detected` | Bad number; flag for cleanup |
| **voicemail** | `voicemail_detected` | Voicemail left; plan retry |
| **completed** | `conversation_completed` | Call completed successfully |
| **unknown** | `unknown_outcome` | Unclear outcome; manual review |

## MemoryEvent Type Definitions

### **MemoryEvent Object**

```typescript
interface MemoryEvent {
  // Identifiers
  memoryEventId: string;        // Unique ID (mem_timestamp_random)
  memoryType: MemoryType;       // Type of memory (lead_interest_detected, etc.)
  source: MemoryEventSource;    // Where it came from (call_outcome, manual, system)

  // Linking
  sourceId: string;             // outcomeId
  workerBriefId: string | null; // Link to brief (if mapped)
  conversationId: string;       // Link to conversation

  // Data
  confidence: number;           // 0-1, inherited from outcome
  payload: {
    summary?: string;           // Outcome summary
    recommendedAction?: string; // What to do next
    callDuration?: number;      // Call length in seconds
    [key: string]: unknown;     // Extensible
  };

  // Metadata
  createdAt: string;            // ISO timestamp
}
```

### **MemoryType Values**

```typescript
type MemoryType =
  | "lead_interest_detected"      // High-value signal
  | "callback_requested"          // Scheduled signal
  | "lead_disqualified"           // Negative signal
  | "wrong_number_detected"       // Data quality signal
  | "voicemail_detected"          // Retry signal
  | "conversation_completed"      // Completion signal
  | "unknown_outcome";            // Uncertain signal
```

### **MemoryEventSource Values**

```typescript
type MemoryEventSource =
  | "call_outcome"  // Generated from webhook outcome
  | "manual"        // User-created
  | "system";       // Generated by system
```

## Integration: How It Works

### **When Webhook Arrives**

```
1. Webhook received
   POST /api/webhooks/elevenlabs
   
2. Conversation saved
   conversationStore.saveConversation()
   
3. Outcome generated
   processAndStoreOutcome(conversation, workerBriefId)
   
4. MemoryEvent created ← ← ← NEW
   processCallOutcomeToMemoryEvent(callOutcome)
   
5. Result:
   - Conversation stored
   - Outcome stored
   - MemoryEvent stored
   
6. HTTP 200 returned
```

### **In Code**

```typescript
// lib/voice/outcomes/call-outcome-processor.ts

export function processAndStoreOutcome(
  conversation: CapturedElevenLabsConversation,
  workerBriefId: string | null = null
): CallOutcome {
  // Build and store outcome
  const outcome = buildCallOutcomeFromConversation(conversation, workerBriefId);
  outcomeStore.saveOutcome(outcome);

  // Convert to memory event ← ← ← NEW IN 12A-5
  processCallOutcomeToMemoryEvent(outcome);

  return outcome;
}
```

## Example Flows

### **Flow 1: Interested Prospect → Lead Interest Detected**

**Webhook arrives**:
```json
{
  "type": "post_call_transcription",
  "data": {
    "conversation_id": "conv_abc123",
    "summary": "Prospect very interested in product",
    "call_duration": 287
  }
}
```

**Outcome generated**:
```json
{
  "outcomeId": "outcome_def456",
  "outcome": "interested",
  "confidence": 0.85,
  "conversationId": "conv_abc123",
  "workerBriefId": "brief_qual_001"
}
```

**MemoryEvent created**:
```json
{
  "memoryEventId": "mem_ghi789",
  "memoryType": "lead_interest_detected",  ← ← ← MAPPED FROM "interested"
  "source": "call_outcome",
  "sourceId": "outcome_def456",
  "conversationId": "conv_abc123",
  "workerBriefId": "brief_qual_001",
  "confidence": 0.85,
  "payload": {
    "summary": "Prospect very interested in product",
    "recommendedAction": "schedule_demo"
  }
}
```

**Next step**: Memory system uses `lead_interest_detected` to update brief's success rate and learned patterns.

### **Flow 3: Wrong Number → Wrong Number Detected**

⚠️ No feedback mechanism (Phase 12C will add)

## Next Phase: 12C Memory System

Phase 12C will:
1. Query memory events by brief
2. Calculate success rates
3. Identify patterns
4. Feed back to brief strategy
5. Create learning loop

Example:
```
If brief_qual_001 has:
  ✓ 80% lead_interest_detected
  ✓ 15% callback_requested
  ✗ 5% lead_disqualified

Then adjust:
  - Keep the question that works
  - Remove disqualifying content
  - Perfect callback timing
```
