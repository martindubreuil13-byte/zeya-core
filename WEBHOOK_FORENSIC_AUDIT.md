### 4. Does the payload actually contain transcript?

**Answer:** YES, if validation passes.

**Evidence:** 
- [Validator line 22](lib/voice/events/elevenlabs-event-validator.ts#L22): 
  ```typescript
  if (!Array.isArray(data.transcript)) return false;
  ```
- If webhook doesn't have a transcript array, validation FAILS and webhook is rejected
- Only validated webhooks reach the processor

**Therefore:** If we receive a `post_call_transcription` event, it MUST have a transcript array.

### 5. Does the payload actually contain summary?

**Answer:** MAYBE. Summary is optional.

**Evidence:**

- Validator does NOT check for summary (line 14-24 only check for required fields)
- A `post_call_transcription` event CAN be missing `summary`

**Critical Issue:** ElevenLabs is sending `post_call_transcription` events with NO summary field (or empty string).

### 6. Are there multiple webhook events for the same conversation?

**Answer:** POSSIBLY YES.

**Evidence:**
- [Validator accepts two relevant event types:](lib/voice/events/elevenlabs-event-validator.ts#L36-L49)
  1. `post_call_transcription` — sent when conversation is done (with transcript + summary)
  2. `post_call_audio` — sent separately when audio is ready

**Theory:** Zeya may be processing webhook events in the wrong order:
- First event: `post_call_audio` event (early, before summary ready)
- Second event: `post_call_transcription` event (later, with full summary)

Or: `post_call_transcription` event sent before summary is generated by ElevenLabs.

### 7. Is Zeya processing an earlier event before ElevenLabs finishes generating summary?

**Answer:** YES. This is the most likely scenario.

**Evidence:**
- [Event validator line 36](lib/voice/events/elevenlabs-event-validator.ts#L36): Only `post_call_transcription` type creates outcomes

- But processor only handles `post_call_transcription` events
- **The processor would receive post_call_transcription event BEFORE ElevenLabs finishes generating the summary field**

This explains the symptom:
- ✅ Transcript received (required field, validator checks it)
- ❌ Summary missing (optional field, webhook sent before ElevenLabs generates summary)

## Root Causes Identified

### **Issue 1: Summary Missing (HIGH PRIORITY)**
- **Where:** `post_call_transcription` webhook arrives with NO `summary` field
- **Why:** ElevenLabs sends the webhook before generating final summary
- **Evidence:** [event-processor.ts:39](lib/voice/events/elevenlabs-event-processor.ts#L39) just copies `data.summary` which is undefined
- **Result:** Defaults to "No summary provided" at [call-outcome-processor.ts:41](lib/voice/outcomes/call-outcome-processor.ts#L41)
- **Fix Required:** Wait for `summary` to be available, or implement webhook retry logic

### **Issue 2: Transcript Persistence (MEDIUM PRIORITY - FIXED)**
- **Where:** [outcome-repository.ts](lib/voice/persistence/outcome-repository.ts)
- **Before Fix:** `transcript: outcome.extractedData` ← WRONG
- **After Fix:** `transcript: outcome.transcript` ← CORRECT
- **Status:** ✅ FIXED in recent commit

## Conclusion

**The webhook is arriving before ElevenLabs generates the final summary.**

The `post_call_transcription` webhook event is sent with:
- ✅ Transcript array (validated, required)
- ❌ Summary field missing or empty (optional field, not yet generated)
- ❌ This is the webhook you're receiving, not a partial/early event

**Action Required:**
1. Implement webhook retry logic to re-fetch summary when it arrives later
2. Or request ElevenLabs to only send `post_call_transcription` after summary is available
3. Or poll for summary completion before creating call_outcomes
